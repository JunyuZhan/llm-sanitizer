# LLM Sanitizer 开发文档

面向参与本项目的工程师:架构、模块、设计决策、扩展方式、测试与发布。

## 1. 架构总览

```
┌────────────┐   HTTP/SSE     ┌──────────────────────┐   转发(已脱敏)   ┌───────────┐
│  AI Agent  │───────────────▶│  gateway  (8790)     │───────────────▶│  上游 LLM  │
│ Codex 等   │◀───────────────│  脱敏→转发→还原       │◀───────────────│ DeepSeek等│
└────────────┘   还原后的响应  └─────────┬────────────┘                 └───────────┘
                                        │ 事件写入 JSONL(只含占位符,不含明文)
                               ┌────────▼────────────┐
                               │ dashboard (8791)    │◀── 浏览器 http://127.0.0.1:8791
                               │ 轮询事件文件渲染看板 │
                               └─────────────────────┘
```

进程模型:`pip install llm-sanitizer-gateway` 后 `llm-sanitizer start`(或源码 `python3 -m llm_sanitizer start`)在一个进程内以线程方式同时运行 gateway 与 dashboard(纯标准库,无外部依赖)。

## 4. 模块说明

### masker.py(脱敏规则引擎,待实现)
- `Masker`:管理 `原文→token`(`reverse`)与 `token→原文`(`mapping`)双向映射,计数器按类别递增;`load_mapping()` 支持重启恢复。
- `mask_text(text, masker=None)`:按规则顺序替换,同一原文复用同一 token。
- 规则清单:身份证(18 位校验和 / 15 位 / 疑似兜底)、手机、座机、邮箱、统一社会信用代码、公司名称(行政区划+字号+行业+组织形式,关键词向左扩展,区分泛称)、司法机关名称(关键词+向左扩展+句法边界)、姓名(角色上下文+姓氏库+停用词)、地址、出生日期、银行账号(16-19 位+Luhn 校验)、案号((年份)+机关简称+编号)、车牌号、护照/证件号、密钥/令牌(sk-/ghp_ 等前缀与 password/token 字段)。
- `restore_text(text, mapping)`:精确回填。
- 独立性:可单独作为文件脱敏 CLI 使用(`mask` / `restore`),亦可作为库导入。

### config.py(配置)
- 端口、上游、数据目录全部可用环境变量覆盖(见 [quickstart](../docs/quickstart.zh-CN.md#3-配置))。
- 类别配置(FR-15):`LLM_SANITIZER_CATEGORIES` 环境变量或数据目录下 `categories.json`,声明启用的类别集合;未配置时默认全量。控制台设置表单(FR-13)写入同一配置,权限 600。
- **工程约束**:每条规则必须附命中样例与误报样例;`RULES` 按顺序匹配,先命中者胜。
- **类别可配置(FR-15)**:每条规则携带唯一类别 id;`Masker(disabled_categories=set)` 按启用集合过滤规则;预设(高敏感/办公/自定义)与用户词表(已实现,v0.2)均作用于规则层之上,引擎接口不变。

### events.py(事件存储)
- JSONL 文件(默认 `~/.llm-sanitizer/events.jsonl`),追加写。
- 事件类型:`mask`(category/token/time)、`request`(path/method/new_findings/total);`startup` 为**预留类型**,当前实现不产生,落地时补发。
- **只写占位符与类别,不写明文**(明文只在 `map.json`)。
- `snapshot()` / `stats()` 供看板使用。
- **实现要求**:追加写与 map.json 一致,统一走"敏感文件写入器"(原子写 + chmod 600);`stats()` 的累计计数改为读取持久化 per-category 计数器(FR-5 口径),不得用内存/尾部事件推算。

### gateway.py(HTTP 代理)
- 仅监听 127.0.0.1。
- 请求路径统一映射:客户端路径去 `/v1` 前缀后拼到上游 base,兼容 OpenAI 与 DeepSeek 两种风格。
- 请求体:`mask_json()` 对 `MASK_KEYS = {content, text, input, instructions, prompt, system, description}` 递归脱敏;**认证字段(Authorization 头、请求体 `api_key`)不参与脱敏**。
- 响应体:SSE 按事件流处理;`StreamRestorer` 用"可保留后缀"算法处理 token 分片;`response.output_text.delta/done`、`reasoning_text.*`、`reasoning_summary.*`、`response.completed`、Chat Completions `delta/message` 均还原。
- 每次请求写事件 + 更新 `map.json`(崩溃可恢复)。
- **实现要求(修复已知缺陷)**:`map.json` 写入必须持锁;工具调用参数(`function_call_arguments`、`tool_calls[].function.arguments`)纳入还原范围;`_transform_event` 的兜底分支必须使用还原后的返回值。
- **实现要求(防浏览器侧攻击,FR-8)**:校验 `Host` 头(仅接受 `127.0.0.1`/`localhost`);拒绝跨域 `Origin`;关键写接口加本地令牌/CSRF 保护。

### dashboard.py(实时看板 + 控制台)
- 独立端口 8791,浏览器访问。
- `GET /`:单页 HTML(原生 JS,每 2 秒轮询 `/api/status`)。
- `GET /api/status`:读取持久化 per-category 计数器(FR-5 口径)与事件文件最近 N 条,返回累计脱敏数、类别分布、请求记录。**累计数来自持久化计数,不因事件条数限制而倒退。**
- 看板不展示明文。
- **控制台化规划(v0.1)**:首启自动打开引导向导页(FR-11,v0.1 为"检测+手动指引"版);增加设置表单(上游地址/密钥,写本机配置文件而非环境变量)与文件脱敏入口(FR-13/FR-14)。
- **实现要求**:修复"运行状态圆点"样式反转缺陷;拒绝跨域 Origin;设置写接口加本地令牌/CSRF 保护(FR-8)。

### config_manager.py(一键接入/还原,FR-12,已实现)
- 检测常见 Agent 配置:Codex `~/.codex/config.toml`、WorkBuddy 自定义模型等。
- 三步操作:`detect()`(发现配置)→ `backup()`(备份原文件)→ `apply()`(写入网关 base_url)/ `restore()`(还原备份)。
- 原则:任何修改先备份、界面可见、可一键还原;TOML 解析在 v0.2 引入 `tomllib`(3.11+)或文本级安全改写。
- **范围边界**:v0.1 引导向导(FR-11)只复用其 `detect()` 做"检测+手动指引",`apply/restore` 随 FR-12 在 v0.2 落地。

### cli.py(命令行)
```
llm-sanitizer start             # 前台启动(网关+看板)
llm-sanitizer status            # 查看运行状态与统计
llm-sanitizer mask 文件 [--categories 姓名,手机号] [--map map.json]  # 单文件脱敏
llm-sanitizer restore 文件 --map map.json   # 单文件还原
./install.sh                    # 安装为开机自启
```
- **接口契约(v0.1 实现,与 FAQ/FR-15 对齐)**:`mask --categories`(类别过滤,逗号分隔)、`mask --map`(导出映射,权限 600)、网关 `--key` 覆盖上游密钥(或环境变量 `LLM_SANITIZER_KEY`)。
- **实现要求**:修复 `status` 子命令的模块导入缺陷(顶层 `from events import ...` 应改为包内相对导入);`--map` 写入的映射文件必须走"敏感文件写入器"(chmod 600)。

## 5. 关键设计决策(ADR)

| 编号 | 决策 | 理由 |
|---|---|---|
| ADR-1 | 纯标准库,零依赖 | 普通用户无需 pip/venv(安装脚本场景);发布 PyPI 后依赖仍为零,降低供应链风险 |
| ADR-2 | token 格式 `[类别_序号]`,跨请求一致 | 还原可依赖、看板可读、映射可持久化 |
| ADR-3 | 事件文件只存占位符不存明文 | 看板/日志可安全展示,减少明文落盘 |
| ADR-4 | 流式还原用"保留 token 前缀后缀"算法 | SSE 分片可能把 token 切碎,需跨事件缓冲 |
| ADR-5 | 请求路径统一去 `/v1` 前缀 | 兼容 OpenAI 与 DeepSeek 两种 base_url 风格 |
| ADR-6 | 每请求后写 `map.json` | 崩溃/重启后 token 不漂移 |
| ADR-7 | 仅监听 127.0.0.1 | 最小攻击面,非系统级代理 |
| ADR-8 | **PyPI 发布为主,源码运行为备**(新增) | "安装更方便"核心诉求;`llm-sanitizer` 控制台入口 + `python3 -m` 双入口 |
| ADR-9 | **映射空间隔离**(新增) | CLI 与网关各持独立映射/计数器,禁止混用,避免 `[姓名_1]` 指向不同原文 |
| ADR-10 | **文档先行 + 双语核心覆盖**(新增) | 开源可读性:README/QUICKSTART/SECURITY/FAQ/EXTENDING 双语,深度文档以中文维护并声明语言策略 |
| ADR-11 | **扩展点分层**(新增) | 规则→词表→Agent→格式处理器四层,难度递增,接口契约先文档化(v0.1)再实现 |
| ADR-12 | **浏览器即界面,零依赖保小白体验**(新增) | 引导向导/控制台复用现有 http.server + 原生 JS,不引入 GUI/托盘依赖(保持 ADR-1);原生托盘类体验用浏览器常驻标签页替代 |
| ADR-13 | **协议适配层解耦 Agent 支持**(新增) | Agent 支持按协议分层:OpenAI 兼容直通(零代码);非 OpenAI 协议(Anthropic/Google)经适配器转统一消息模型。新增 Agent 不动核心,只加适配器与注册表条目 |
| ADR-14 | **界面层与内核解耦,桌面包装为可选特性**(新增) | 形态演进:本地 Web 控制台 → pywebview 桌面轻包(v0.2)→ Tauri/PyInstaller 独立安装包(v0.3)→ 企业私有化(远期);内核(网关/引擎/存储)不变。桌面依赖(如 pywebview)声明为可选特性(`pip install llm-sanitizer-gateway[desktop]`),核心零依赖承诺(ADR-1)不受影响;明确不做公网 SaaS |

## 6. 数据流

### 请求方向
1. Agent 以 base_url=`http://127.0.0.1:8790/v1` 发起请求。
2. gateway 读取 JSON 请求体,`mask_json` 脱敏文本字段。
3. 记录新增 token 事件(只含占位符),写 `map.json`。
4. 转发给上游(保留 Authorization,可选 `--key`/环境变量覆盖)。

### 响应方向
1. 上游返回 SSE 或 JSON。
2. SSE:逐事件处理,`StreamRestorer.feed()` 还原 delta,`done/completed` 整段还原。
3. JSON:`restore_json()` 还原 `content/text/summary` 字段。
4. 按原格式(SSE 保持事件流、chunked 编码)回写客户端。

## 7. 性能与错误处理考虑

- **性能**:脱敏为文本字段上的正则 + 字典查找,单请求毫秒级;流式还原仅增加小缓冲。无网络绕路。
- **并发**:`ThreadingHTTPServer` + 全局 `state`。脱敏写、还原读共享 `masker.mapping`;写入路径(含 `map.json` 落盘)必须统一持锁。
- **错误处理**:请求 JSON 解析失败 → 400;上游不可达 → 502 并释放连接;上游返回非 JSON → 原样透传(不强行解析)。
- **超大响应**:非 SSE 响应全量读入内存,SSE 逐行流式;v0.2 可考虑分块写回。

### 8.1 新 Agent 接入(协议适配层,ADR-13)

**关键认知:Agent 支持被协议绑定,而非被"名字"绑定。** 分两种情况:

- **OpenAI 兼容客户端**(Codex、WorkBuddy、Cline、OpenClaw 及任意走 Responses / Chat Completions 的工具):`base_url` 指向网关即可,**零代码接入**。
- **非 OpenAI 协议客户端**(Claude Code → Anthropic Messages API、Gemini CLI → Google generateContent):请求结构完全不同(`content` 是数组、`system` 在顶层、`contents/parts` 嵌套),直接按 OpenAI 的 `MASK_KEYS` 脱敏会漏检或转发失败——**必须经适配器转换**。

架构(核心保持协议无关):

```
Agent → 各自协议 → Adapter(parse → extract → mask → rebuild) → 统一消息模型 → 脱敏/还原引擎
```

- `adapters/base.py`:`Adapter` 抽象类 —— `parse_request` / `extract_text_fields` / `rebuild_request` / `restore_response` + SSE 事件类型映射。
- `adapters/openai.py`:Responses + Chat Completions(兼容直通,v0.1 即含)。
- **Anthropic Messages(v0.2 已实现)**:网关原生兼容——转发白名单含 `anthropic-version`;上游为 anthropic.com 时密钥注入 `x-api-key`(其余 Bearer);SSE 事件 `content_block_delta`(text_delta)走流式缓冲还原、`message_stop` 重置;响应 `tool_use.input`(任意 JSON)整体还原。Claude Code 接入见 [AGENTS.md](AGENTS.md)。
- `adapters/gemini.py`:规划(v0.3)。
- `adapters/registry.py`:按路径/协议头路由到适配器。**新增 Agent = 注册表条目 + (协议不同时)一个适配器,核心零改动。**

**协议支持矩阵**(规划):

| Agent | 协议 | 支持方式 | 版本 |
|---|---|---|---|
| Codex / WorkBuddy / OpenClaw / Cline | OpenAI(Responses/Chat) | 直通(base_url) | v0.1 ✅ |
| 任意 OpenAI 兼容客户端 | OpenAI | 直通 | v0.1 ✅ |
| Claude Code | Anthropic Messages | 适配器(网关原生兼容,含 SSE/工具/密钥) | v0.2 ✅ |
| Gemini CLI / Gemini API | Google generateContent | 适配器(含 streamGenerateContent SSE 分片还原) | v0.2 ✅ |

### 8.2 模型与服务商覆盖(按协议归类)

模型数量庞大,但 API 协议收敛为三类。网关按协议覆盖,**同一协议内的全部服务商/模型即插即用**(base_url 指向网关即可):

| 协议 | 覆盖的服务商 / 模型(节选) | 网关状态 |
|---|---|---|

### 8.3 其他扩展点

1. **自定义规则**:`masker.py` 中追加正则 + 类别,必须附命中/误报双向测试。
2. **自定义词表(已实现,v0.2)**:数据目录 `wordlist.txt`,每行一个词(可 `词|类别`,默认类别「自定义词表」);`Masker(wordlist=[...])` 加载,词表优先于正则;CLI `mask --wordlist` 与看板 `/api/wordlist` 可维护;词须独立成词(前后非 CJK/字母/数字),防子串误伤。
3. **新文档格式(已实现 docx/xlsx,v0.2)**:格式处理器(`formats.py`)在 ZIP/XML 层面改写文本节点,格式与样式原样保留;CLI `mask/restore` 按扩展名自动分发。PDF 纯标准库文本提取不可靠,暂不内置(v0.3 评估)。新格式接入 = 在 `formats.py` 加解析/重建,复用 `mask_text`/`restore_text`。
