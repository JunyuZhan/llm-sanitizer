# LLM Sanitizer 开发文档

面向参与本项目的工程师:架构、模块、设计决策、扩展方式、测试与发布。

## 1. 架构总览

```
┌────────────┐   HTTP/SSE     ┌──────────────────────┐   转发(已脱敏)   ┌───────────┐
│  AI Agent  │───────────────▶│  gateway  (8790)     │───────────────▶│  上游 LLM  │
│ Codex 等   │◀───────────────│  脱敏→转发→还原       │◀───────────────│ DeepSeek等│
└────────────┘   还原后的响应  └─────────┬────────────┘                 └───────────┘
                                        │ 事件写入 JSONL(只含占位符,不含明文)
                               ┌────────▼────────────┐
                               │ dashboard (8791)    │◀── 浏览器 http://127.0.0.1:8791
                               │ 轮询事件文件渲染看板 │
                               └─────────────────────┘
```

进程模型:`pip install llm-sanitizer` 后 `llm-sanitizer start`(或源码 `python3 -m llm_sanitizer start`)在一个进程内以线程方式同时运行 gateway 与 dashboard(纯标准库,无外部依赖)。

## 4. 模块说明

### masker.py(脱敏规则引擎,待实现)
- `Masker`:管理 `原文→token`(`reverse`)与 `token→原文`(`mapping`)双向映射,计数器按类别递增;`load_mapping()` 支持重启恢复。
- `mask_text(text, masker=None)`:按规则顺序替换,同一原文复用同一 token。
- 规则清单:身份证(18 位校验和 / 15 位 / 疑似兜底)、手机、座机、邮箱、统一社会信用代码、司法机关名称(关键词+向左扩展+句法边界)、姓名(角色上下文+姓氏库+停用词)、地址、出生日期。
- `restore_text(text, mapping)`:精确回填。
- 独立性:可单独作为文件脱敏 CLI 使用(`mask` / `restore`),亦可作为库导入。
- **工程约束**:每条规则必须附命中样例与误报样例;`RULES` 按顺序匹配,先命中者胜。

### events.py(事件存储)
- JSONL 文件(默认 `~/.llm-sanitizer/events.jsonl`),追加写。
- 事件类型:`mask`(category/token/time)、`request`(path/method/new_findings/total)、`startup`。
- **只写占位符与类别,不写明文**(明文只在 `map.json`)。
- `snapshot()` / `stats()` 供看板使用。

### gateway.py(HTTP 代理)
- 仅监听 127.0.0.1。
- 请求路径统一映射:客户端路径去 `/v1` 前缀后拼到上游 base,兼容 OpenAI 与 DeepSeek 两种风格。
- 请求体:`mask_json()` 对 `MASK_KEYS = {content, text, input, instructions, prompt, system, description}` 递归脱敏。
- 响应体:SSE 按事件流处理;`StreamRestorer` 用"可保留后缀"算法处理 token 分片;`response.output_text.delta/done`、`reasoning_text.*`、`reasoning_summary.*`、`response.completed`、Chat Completions `delta/message` 均还原。
- 每次请求写事件 + 更新 `map.json`(崩溃可恢复)。
- **实现要求(修复已知缺陷)**:`map.json` 写入必须持锁;工具调用参数(`function_call_arguments`、`tool_calls[].function.arguments`)纳入还原范围;`_transform_event` 的兜底分支必须使用还原后的返回值。

### dashboard.py(实时看板)
- 独立端口 8791,浏览器访问。
- `GET /`:单页 HTML(原生 JS,每 2 秒轮询 `/api/status`)。
- `GET /api/status`:从事件文件读取最近 N 条,计算累计脱敏数、类别分布、请求记录。
- 看板不展示明文。
- **实现要求**:修复"运行状态圆点"样式反转缺陷。

### cli.py(命令行)
```
llm-sanitizer start             # 前台启动(网关+看板)
llm-sanitizer status            # 查看运行状态与统计
llm-sanitizer mask 文件          # 单文件脱敏(复用 masker)
llm-sanitizer restore 文件 --map map.json   # 单文件还原
./install.sh                    # 安装为开机自启
```
- **实现要求**:修复 `status` 子命令的模块导入缺陷(顶层 `from events import ...` 应改为包内相对导入)。

## 5. 关键设计决策(ADR)

| 编号 | 决策 | 理由 |
|---|---|---|
| ADR-1 | 纯标准库,零依赖 | 普通用户无需 pip/venv(安装脚本场景);发布 PyPI 后依赖仍为零,降低供应链风险 |
| ADR-2 | token 格式 `[类别_序号]`,跨请求一致 | 还原可依赖、看板可读、映射可持久化 |
| ADR-3 | 事件文件只存占位符不存明文 | 看板/日志可安全展示,减少明文落盘 |
| ADR-4 | 流式还原用"保留 token 前缀后缀"算法 | SSE 分片可能把 token 切碎,需跨事件缓冲 |
| ADR-5 | 请求路径统一去 `/v1` 前缀 | 兼容 OpenAI 与 DeepSeek 两种 base_url 风格 |
| ADR-6 | 每请求后写 `map.json` | 崩溃/重启后 token 不漂移 |
| ADR-7 | 仅监听 127.0.0.1 | 最小攻击面,非系统级代理 |
| ADR-8 | **PyPI 发布为主,源码运行为备**(新增) | "安装更方便"核心诉求;`llm-sanitizer` 控制台入口 + `python3 -m` 双入口 |
| ADR-9 | **映射空间隔离**(新增) | CLI 与网关各持独立映射/计数器,禁止混用,避免 `[姓名_1]` 指向不同原文 |
| ADR-10 | **文档先行 + 双语核心覆盖**(新增) | 开源可读性:README/QUICKSTART/SECURITY/FAQ/EXTENDING 双语,深度文档以中文维护并声明语言策略 |
| ADR-11 | **扩展点分层**(新增) | 规则→词表→Agent→格式处理器四层,难度递增,接口契约先文档化(v0.1)再实现 |

## 6. 数据流

### 请求方向
1. Agent 以 base_url=`http://127.0.0.1:8790/v1` 发起请求。
2. gateway 读取 JSON 请求体,`mask_json` 脱敏文本字段。
3. 记录新增 token 事件(只含占位符),写 `map.json`。
4. 转发给上游(保留 Authorization,可选 `--key`/环境变量覆盖)。

### 响应方向
1. 上游返回 SSE 或 JSON。
2. SSE:逐事件处理,`StreamRestorer.feed()` 还原 delta,`done/completed` 整段还原。
3. JSON:`restore_json()` 还原 `content/text/summary` 字段。
4. 按原格式(SSE 保持事件流、chunked 编码)回写客户端。

## 7. 性能与错误处理考虑

- **性能**:脱敏为文本字段上的正则 + 字典查找,单请求毫秒级;流式还原仅增加小缓冲。无网络绕路。
- **并发**:`ThreadingHTTPServer` + 全局 `state`。脱敏写、还原读共享 `masker.mapping`;写入路径(含 `map.json` 落盘)必须统一持锁。
- **错误处理**:请求 JSON 解析失败 → 400;上游不可达 → 502 并释放连接;上游返回非 JSON → 原样透传(不强行解析)。
- **超大响应**:非 SSE 响应全量读入内存,SSE 逐行流式;v0.2 可考虑分块写回。

## 8. 扩展指南

详见 [extending.md](extending.md)(双语)与 [需求文档 FR-10](需求文档.md)。要点:

1. **自定义规则**:`masker.py` 中追加正则 + 类别,必须附命中/误报双向测试。
2. **自定义词表**:v0.2,用户词表文件,优先于正则检查。
3. **新 Agent**:纯配置(base_url 指向网关),无需改代码。
4. **新文档格式**:格式处理器(解析→脱敏→重建)独立于 masker,支持多格式扩展。

## 9. 已知实现缺陷(v0.1 必须修复)

以下缺陷在代码审查中发现,已列入 v0.1 修复清单:

| 编号 | 缺陷 | 影响 |
|---|---|---|
| D1 | `cli.py` `status` 子命令顶层导入 `from events import ...` | 以 `-m` 方式运行时必崩 |
| D2 | `_transform_event` 兜底分支丢弃 `restore_json` 返回值 | 未覆盖的事件类型不还原 |
| D3 | 工具调用参数(`function_call_arguments` / `tool_calls[].function.arguments`)不在还原范围 | 响应残留占位符(风险 R7) |
| D4 | `map.json` 写入未持锁 | 并发请求竞态覆盖(风险 R9) |
| D5 | 看板"运行状态"圆点样式逻辑反转 | 正常运行时显示红色 |
| D6 | 上游不可达时连接未释放 | 连接泄漏 |

## 10. 运行与测试

```bash
# 运行(源码)
python3 -m llm_sanitizer start

# 运行(发布后)
pip install llm-sanitizer && llm-sanitizer start

# 端到端测试(启动 mock 上游 + 网关,断言脱敏与还原)
python3 tests/test_e2e.py
```

测试通过标准:
- 上游收到的请求体中不含测试原文,只含 `[类别_序号]`。
- 客户端收到的流/消息为还原后的原文。
- 看板 `/api/status` 返回最近事件。
- 规则误报率回归测试不增。

## 12. 发布

- **v0.1**:补齐缺失模块与修复 D1~D6 → `pyproject.toml` 打包 → 发布 PyPI(`pip install llm-sanitizer`)。
