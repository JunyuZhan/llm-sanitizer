# LLM Sanitizer 需求文档(PRD)

版本:v0.1(已发布)　日期:2026-08-27　状态:已发布

> **实现状态**:v0.1 已发布(2026-08-27)——规则引擎、网关、控制台、CLI、安装脚本、测试套件(29 用例)与 CI 全部落地。模块实现状态见[开发文档 §2](开发文档.md#2-模块与实现状态)。

## 1. 项目背景

AI Agent 工具(Codex、WorkBuddy、OpenClaw、Claude Code、Cline 等)在处理本地任务时,会读取本地文件并把内容发送给云端大模型。对律师、法务等群体,这些文件(起诉状、判决书、合同、证据材料)通常包含姓名、身份证号、手机号、住址、司法机关名称等个人隐私数据。当前用户只有两个选择:**不用 Agent**,或 **裸奔**(数据直接出网)。

需要一个本地、透明、可审计的中间层:数据在出网前被自动脱敏,用户能实时看到脱敏过程,从而建立信任、放心使用 Agent。

## 2. 项目定位

一句话:**本地运行的"AI 流量隐私网关",自动脱敏出网内容、精确还原返回内容,并用实时看板让脱敏过程可见。**

开源定位:MIT 许可、GitHub 托管、面向中文用户为主(核心文档双语)、社区可扩展、纯标准库零依赖、可独立审计。

## 3. 目标用户

| 用户 | 场景 |
|---|---|
| 律师 / 法务 / 公检法相关从业者(核心) | 把判决书、合同、证据交给 Agent 分析 |
| 企业办公中处理个人信息的员工 | HR、财务、客服等 |
| 隐私敏感的个人用户 | 日常使用 AI 助手 |
| Agent 工具厂商 / 企业 IT | 嵌入或部署为组织级隐私层 |
| 开源贡献者 | 扩展规则、接入新 Agent、新文档格式 |

## 4. 核心目标(Goals)

- **G1 防泄漏**:Agent 出网内容中可识别的隐私信息被替换为占位符,真实信息不出网。
- **G2 可用性**:对用户透明,响应还原后体验与未脱敏一致。
- **G3 可信任**:实时看板让用户看到"什么被脱敏了",建立信任。
- **G4 易安装**:一条命令安装(`pip install llm-sanitizer-gateway` 为主推路径),开机自启,卸载干净。
- **G5 可扩展**:脱敏规则、支持的 Agent、文档格式、语言规则均可扩展。

## 5. 非目标(Non-Goals)

- 不做系统级全局流量劫持:只拦截配置中指向网关的 Agent 流量,不影响其他软件。
- 不做云端处理:全部在本机完成。
- 不承诺匿名化:脱敏 ≠ 匿名化,组合字段仍可能重新识别个人。
- 不替代法律合规咨询(个人信息保护法 / 律师保密义务等)。
- 不做防火墙/请求阻断:只改写内容,不做允许/拒绝。
- **不做公网在线 SaaS**:用户明文经云端中转与"数据不出本机"的定位冲突,且引入服务器信任问题。Web 形态仅限:本地 Web 控制台(现状演进)与企业私有化部署(数据留在客户内网,远期)。
- v0.2 起支持 WebSocket 透明代理(帧级转发,文本消息脱敏/还原,见开发文档 §websocket)。
- 不承诺工具调用参数的完整还原(见风险 R7)。

## 6. 功能需求(FR)

### FR-1 本地网关
- 仅监听 `127.0.0.1`,默认端口 8790。
- 支持 OpenAI **Responses API**(`/v1/responses`)与 **Chat Completions**(`/v1/chat/completions`)。
- 支持 SSE 流式响应与普通 JSON 响应。
- 上游地址可配置(OpenAI 风格 base 带 `/v1`、DeepSeek 风格不带 `/v1` 均兼容)。

### FR-2 中文敏感信息识别
| 类别 | 说明 |
|---|---|
| 姓名 | 角色上下文(原告/被告/法定代表人/审判长…)+ 姓氏库,避免误伤"认为/请求" |
| 身份证号 | 18 位校验和验证;形似 18 位但校验失败标"疑似";15 位老证 |
| 手机号 / 座机号 | 1[3-9] 11 位;区号固话 |
| 邮箱 | 标准邮箱格式 |
| 统一社会信用代码 | 18 位字符集校验 |
| 公司名称 | 行政区划+字号+行业+组织形式结构识别(如"深圳XX科技有限公司"),关键词(有限公司/集团/股份/控股/银行/医院…)向左扩展;**泛称("公司/企业/乙方")不脱敏** |
| 司法机关名称 | 人民法院、检察院、公安、仲裁委、律所等,关键词+向左扩展+句法边界 |
| 地址 | 住址/住所地/户籍地等上下文词后的取值 |
| 出生日期 | 出生日期/出生年月/生日上下文 |
| 银行账号 | 银行卡号(16-19 位 + Luhn 校验)与银行账户(户名+账号+开户行),开户行/收款账户/银行账号等上下文词辅助 |
| 案号 | (年份)+机关简称+编号,如"（2026）京01民初123号",词边界防误伤;律师检索核心标识,按需可关闭(FR-15) |
| 车牌号 | 省简称+字母+数字(蓝牌 5 位/新能源 6 位) |
| 护照/证件号 | 护照(E+8 位等)、驾驶证、港澳通行证等编号格式 |
| 密钥/令牌 | API key(sk-/ghp_ 等前缀)、password/token 等字段值——**LLM 流量场景最高优先级,默认开启**。**仅作用于内容字段;认证头(`Authorization`)与请求体认证字段(如 `api_key`)不参与脱敏,防止破坏客户端认证** |

> 候选类别(v0.2,与自定义词表同期):社保/医保号、医疗信息(病历号/疾病)、专利/商标注册号、微信号/社交账号、交易金额与发票信息(需评估对合同分析的影响)、未成年人信息增强标记。

> 规则演进:每条规则必须有"命中样例 + 误报样例"双向测试,防止过宽误伤。

### FR-3 一致性与还原
- 同一原文在整个会话中映射到同一占位符(`[姓名_1]`、`[身份证号_2]`……)。
- 映射持久化到本机文件(`map.json`,权限 600),网关重启后 token 不漂移。
- 流式响应中 token 被网络分片(如 `[姓名` / `_1]`)也能正确还原。
- 还原只做**精确回填**;模型改写占位符时不强行还原。
- **CLI 与网关使用独立映射空间**,禁止混用(见风险 R8)。

### FR-4 实时看板
- 本地 Web 页面(默认端口 8791),浏览器打开即可查看。
- 展示:运行状态、累计脱敏数、按类别分布、最近脱敏事件(时间/类别/占位符/请求路径)、最近请求记录。
- **看板不展示明文**:事件流只记录占位符与类别,原文只在用户本机 `map.json` 中。
- v0.1 后续迭代:仅内存的"展开查看脱敏前后片段"用于核对脱敏质量(不落盘)。

### FR-5 请求日志与统计口径
- 每次请求记录:时间、方法、路径、本轮新增脱敏数、累计脱敏数。
- 日志不记录请求体内容。
- **"累计脱敏数"口径(修正)**:基于持久化的 per-category 计数器(随 map.json 一并落盘),而非事件尾部计数——事件文件保留条数有限,按尾部计数会导致数字倒退。计数器随每次脱敏递增,重启不归零、不倒退;看板与 `status` 均读取该持久化计数。

### FR-6 Agent 接入
- 提供 Codex(`~/.codex/config.toml`)、WorkBuddy(自定义模型)、OpenClaw 及通用 OpenAI 兼容客户端的接入步骤。
- 统一模式:把 base_url 指向 `http://127.0.0.1:8790/v1`。

### FR-7 安装与自启
- **主推 `pip install llm-sanitizer-gateway`**(PyPI 发布,列入 v0.1 里程碑);源码运行作为备选。
- macOS:launchd 开机自启;Linux:systemd(用户级);Windows:Roadmap v0.2。
- 卸载无残留(停服务、删配置、删数据目录)。

### FR-8 数据安全
- 仅监听 127.0.0.1。
- `map.json`、事件文件、日志默认权限 600(所有落盘敏感文件统一走"原子写入 + chmod 600"封装,含 CLI `mask --map` 与事件追加写)。
- 事件文件只存占位符/类别/时间,不存明文。
- 日志不记录请求体内容。
- 本机进程可调用网关:v0.1 不设额外鉴权,明确写入威胁模型(本机受信任)。
- **防浏览器侧攻击(硬性要求,v0.1 实现)**:网关校验 `Host` 头(仅接受 `127.0.0.1`/`localhost`,拒绝域名指向本机的情况,防 DNS rebinding);看板/控制台拒绝跨域 `Origin`;关键写接口(设置保存、后续的接入操作)加本地令牌或 CSRF 保护。"浏览器沙箱内恶意网页(DNS rebinding / 跨站请求)"明确列入威胁模型(见 SECURITY)。

### FR-9 文档脱敏 CLI
- `mask` / `restore` 子命令处理单个文件(文本、CSV、JSON、SQL、代码等文本流格式)。
- Word/Excel/PDF 等二进制格式标注为"文本提取后脱敏",保留原格式重建列为 v0.2。

### FR-10 扩展机制
- 自定义规则:正则 + 类别注册,带双向测试要求。
- 自定义词表(已实现,v0.2):用户词表文件 `wordlist.txt`,每行一个词(可 `词|类别`),脱敏引擎优先于正则检查;CLI `mask --wordlist` 与控制台均可维护。
- 新 Agent:纯配置接入,无需改网关。
- 新文档格式:格式处理器(解析→脱敏→重建)独立于 masker 之外(v0.2)。
- 作为库使用:`mask_text` / `restore_text` 公开 API 可独立导入。

### FR-11 首启引导向导(小白体验,零命令行)
- 首次启动自动打开浏览器进入引导页(复用看板端口,纯标准库实现)。
- **v0.1 范围:检测 + 手动指引**。四步流程:① 启动完成(自动)→ ② 检测本机已安装的 Codex / WorkBuddy 等并展示 → ③ 按指引手动接入(展示目标配置片段,用户复制粘贴到对应设置页)→ ④ 验证。
- **不写入配置文件**:v0.1 引导只读不写;自动写入/一键接入属于 FR-12(config_manager,v0.2)。
- 全程无需理解 base_url/端口/环境变量的含义(只需复制粘贴)。

### FR-12 一键接入与一键还原
- 新增 `config_manager` 模块:检测常见 Agent 配置(Codex `~/.codex/config.toml`、WorkBuddy 自定义模型等),**先备份原配置**,再写入网关地址,并记录变更。
- 提供"一键还原"按钮:恢复备份,确保用户可随时回到原状态。
- 原则:绝不静默修改用户配置,每一步操作在界面上可见可撤销。

### FR-13 控制台化看板
- 看板升级为单页控制台:运行状态开关、接入/还原入口、上游设置表单(替代环境变量)、脱敏统计、验证结果展示。
- 上游地址与密钥可在界面填写,写入本机配置文件(权限 600),不强制使用环境变量。

### FR-14 拖拽文件脱敏
- 控制台提供"文件脱敏"区:拖入文件(文本/CSV/JSON/SQL/代码)→ 自动生成 `masked_` 脱敏版供上传,并可下载还原版。
- 复用 `mask`/`restore` CLI 逻辑,Web 端仅做界面壳。

### FR-15 脱敏类别可配置(用户选择脱敏什么)
- 每条内置规则带唯一类别 id(姓名/身份证号/手机号/座机号/邮箱/信用代码/公司名称/司法机关/地址/出生日期/银行账号/案号/车牌号/证件号/密钥令牌),可独立启用/停用。
- 配置途径:控制台设置表单(FR-13)、环境变量/配置文件、CLI `mask --categories`。
- **CLI 接口契约(v0.1 实现)**:`mask --categories 姓名,手机号` 与 `restore --map` 对齐 FAQ/控制台描述;`--key` 覆盖上游密钥随网关一并实现。开发文档与 quickstart 同步补全这两个接口。
- 场景预设:高敏感(全开)/ 办公(姓名+手机号+邮箱+公司名称+地址+银行账号)/ 自定义,一键切换。
- **默认全量开启**;关闭任一类别时必须醒目提示"该类信息将明文出网"并确认,看板持续显示"当前启用 N/15 类"。
- 与用户自定义词表(已实现,v0.2)互补:类别开关管内置规则,词表管用户补充。
- **配置优先级(FR-8/FR-13 统一)**:界面设置 > 环境变量 > 内置默认值。

## 8. 验收标准(AC)

- **AC-1 端到端脱敏**:发送含测试隐私的请求,上游实际收到的内容中不包含原文,只包含占位符(自动化断言)。
- **AC-2 端到端还原**:客户端收到的流与存储消息为还原后的原文。
- **AC-3 看板实时性**:脱敏发生后 2 秒内,看板出现对应事件。
- **AC-4 协议兼容**:Chat Completions 与 Responses API(含流式)均通过端到端测试。
- **AC-5 安装**:`pip install llm-sanitizer-gateway` 后一条命令启动;macOS 开机自启;卸载后无残留文件与服务。
- **AC-6 安全边界**:仅监听 127.0.0.1;`map.json` 权限 600;看板/事件流无明文。
- **AC-7 规则质量**:每条规则通过命中样例与误报样例测试(误报率回归测试)。
- **AC-8 文档**:需求、开发、安全、接入、扩展、FAQ 文档齐全且双语核心覆盖,新工程师可据此独立开发。
- **AC-9 零命令行接入**(v0.1 追加,v0.2 达成):全新用户按引导向导操作,完成"检测 → 一键接入(自动备份,可一键还原)→ 验证 → 看到脱敏事件"的完整闭环,全程不接触命令行;接入后配置可一键还原。

## 9. 已知限制与风险(实测发现,如实记录)

- **R1 传输通道覆盖不全**(v0.2 已修复):部分客户端(含部分桌面 App)走 WebSocket 通道。**v0.2 新增 WebSocket 透明代理**——帧级双向转发,文本消息去程脱敏/回程还原,二进制(音频等)与控制帧透传;支持 http(s)/ws(s) 上游。
- **R2 识别覆盖有限**(v0.2 缓解):正则规则无法覆盖所有姓名、别名、机构简称。**v0.2 新增自定义敏感词表**——用户把正则抓不到的词补入 `wordlist.txt`(每行一词,可 `词|类别`),词表优先于内置规则。
- **R3 显示层差异**:部分 CLI 模式可能显示占位符而非还原原文(不影响出网安全,只影响观感)。
- **R4 二进制文档格式**(v0.2 部分解决):docx/xlsx 已支持保留格式脱敏(CLI `mask`,见开发文档 §formats);PDF 纯标准库文本提取不可靠,v0.3 评估。
- **R5 信任风险**:网关本身能读取内容,属于高信任组件;必须开源、可审计、仅本机运行。
- **R6 文档先行状态**(已解除,2026-08-27):v0.1 代码已全部落地并发布,快速开始命令可用。
- **R7 工具调用参数还原缺口**:模型生成的 tool-call 参数(JSON 字符串)若含占位符,客户端可能看到残留占位符(影响可用性,不影响出网安全)。**修复计划:v0.1 内通过缺陷 D3 修复**;修复完成后本条风险移除,FAQ/AGENTS 的引用同步更新。
- **R8 映射空间冲突**:CLI 与网关各持独立映射与计数器,同一 `[姓名_1]` 可能映射不同原文;混用 map 会还原错误。规范:每个工作流只使用一个映射来源。
- **R9 并发写竞态(实现层)**:`map.json` 全量写入需持锁,否则并发请求可能互相覆盖(列入 v0.1 实现要求)。

## 11. 测试策略

- **验收测试**:对照 AC-1 ~ AC-9。
- **回归测试**:规则误报率随版本演进保持不增(规则质量门禁)。
