# 安全与信任模型

[English](SECURITY.md)

## 1. 定位声明(请先读这段)

**LLM Sanitizer 是一个"中间人"网关。** 它在技术上能够读取、修改、转发你发给模型的所有内容。这是它的功能,也是它的风险。使用本项目前,请先阅读源码,确认它与你的信任预期一致。

## 2. 数据流向

| 阶段 | 数据 | 去向 |
|---|---|---|
| Agent → 网关 | 原始请求体(含对话/文件内容) | 仅在本机内存,脱敏后转发 |
| 网关 → 上游 | 脱敏后的占位符文本 | 你配置的上游 LLM(如 DeepSeek) |
| 上游 → 网关 | 模型响应 | 本机还原后回传 |
| 网关 → 看板/事件文件 | 占位符、类别、时间、请求路径 | 本机 JSONL,**不含明文** |
| `map.json` | 原文 ↔ 占位符映射 | 本机,权限 600 |

## 3. 安全边界

- 仅监听 `127.0.0.1`,外部网络无法访问。
- 不修改系统代理、不安装证书、不劫持非 Agent 流量。
- 只影响配置了 `base_url = http://127.0.0.1:8790/v1` 的客户端。
- 零第三方依赖(纯 Python 标准库),供应链风险低。
- 代码开源,欢迎审计。

## 4. 存储与权限

- `~/.llm-sanitizer/map.json`:原文↔占位符映射。**等同敏感信息本身**,请勿外发、上传、提交到代码库。
- `~/.llm-sanitizer/events.jsonl`:脱敏事件(占位符/类别/时间/请求路径),不含明文,用于看板。
- 日志:仅记录时间、路径、新增脱敏数,不记录请求体。

## 5. 已知限制(务必阅读)

> 编号以[需求文档 §9](../docs/需求文档.md#9-已知限制与风险实测发现如实记录)为权威,此处不重复编号。

- **通道覆盖**:走 WebSocket 等非 HTTP 通道的客户端,v0.1 无法拦截其对话内容。接入前请确认客户端使用 HTTP/SSE 传输(如 Codex CLI 配置 `wire_api = "responses"` 且未启用 WebSocket)。
- **识别覆盖**:正则规则无法识别所有姓名、别名、简称。对高敏感场景,请补充自定义词表(v0.2 提供),或在本地模型/受控环境中处理。
- **脱敏 ≠ 匿名化**:占位符可防止明文外泄,但结合上下文("被告,男,30 岁,深圳")仍可能被推断。
- **还原边界**:只做精确回填;模型改写占位符后无法还原。

## 6. 威胁模型

| 方向 | 是否防御 | 说明 |
|---|---|---|
| Agent / 用户误操作导致隐私出网 | ✅ 缓解 | 数据出本机前已完成脱敏 |
| 第三方 SDK 悄悄附加数据到请求 | ✅ 缓解 | 转发仅白名单请求头;请求体统一脱敏 |
| **浏览器沙箱内的恶意网页(DNS rebinding / 跨站请求)** | ✅ 缓解(v0.1 实现要求) | 网关校验 Host 头(仅 127.0.0.1/localhost)、控制台拒绝跨域 Origin、写接口加本地令牌;防止恶意页面借同源读取还原后的明文(FR-8) |
| 网关本身被植入恶意代码 | ⚠️ 残余风险 | 缓解:代码审计 + 仅回环监听 + 最小权限 + 版本校验 |
| 本机被完全攻陷(恶意软件) | ❌ 不防御 | 用户态工具无法防御本机完全沦陷 |

## 7. 漏洞报告

我们严肃对待安全问题。报告漏洞时:

- **不要**为安全问题开公开 issue。
- 直接通过邮件联系维护者(见 [README](../README.zh-CN.md)),或使用仓库的**私有漏洞报告**通道(如已启用)。
- 请附上:受影响版本、复现步骤、预期与实际行为、修复建议(如有)。
- 我们承诺 48 小时内确认,并与你协调修复与披露时间线。

## 8. 卸载

```bash
./install.sh --uninstall
rm -rf ~/.llm-sanitizer
```

同时把 Agent 的 base_url 改回原值(如 Codex 的 `~/.codex/config.toml` 中 `model_provider` 改回原 provider)。
